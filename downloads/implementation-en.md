# Applying Hatta's Identity

Version 2.2 · 30-10-2026

English implementation instructions for Hatta websites, tools, presentations, reports and social graphics. This is a reference document; downloading it does not install a skill.

## Read the appropriate reference

- Read the [full guide](brand-guide-en.md) before implementing or reviewing the full identity.
- Use the output-specific rules below for the deliverable being produced.
- Use the [tokens](tokens.json) and [CSS](brand.css) for websites.
- For websites and tools, read the [digital experience and skill standards](digital-quality-en.md) and perform the relevant checks. No external skill installation is required.
- Match the version of the reference, tokens and instructions. If they differ, fetch current files together from the same guide. Do not mix releases.

## Define the scope

Infer the work's role, output and audience from the request. Ask only if an unknown relationship between organizations materially affects the work. Task-specific user instructions take priority over this guide; note material exceptions in the handoff.

- **Full identity:** apply the logo, colors, fonts, pattern and voice as needed for the deliverable.
- **Fonts only:** apply font families, weights and alternate forms. Preserve existing colors, logos, content and functionality.
- **Co-branded work:** identify the lead organization and the role of each participant. Use approved original logos and balance their visible size and clear space.
- **Independent platform:** respect its own identity. Using Hatta's fonts or Naif's signature does not imply that the platform belongs to Hatta.

## Implement

1. Use Hatta's logo and Naif's signature from their original assets. Do not retype, redraw or generate them.
2. Preserve proportions, colors and clear space. The site's WebP assets are raster images, not vector files for large-format printing.
3. Apply three fonts in four roles: Thmanyah Serif Display for Arabic main headings; Thmanyah Sans with `salt=1` for Arabic subheadings and highlights; the same family with `salt=0` for Arabic body text, buttons and tables; El Messiri for English.
4. Verify that font files and required features load. Report unavailable fonts; do not claim a fallback is equivalent. Use official font sources and respect their terms. Do not invent redistribution rights.
5. Use navy or the dedicated text-gold shade for small text on light backgrounds. Check contrast for each actual color pair.
6. Use accessible Arabic without general diacritics, digits 0–9 and affirmative headings. Preserve accuracy and necessary terminology. Never invent figures, contact details or partnership roles.
7. Preserve tool functionality, user data and behavior within the requested scope. Rebranding or drawing a result does not authorize changes to calculations.
8. Place Naif's signature according to his role, without repeating his name or handle in the same area or automatically adding a CV link. Hatta's logo leads in Hatta tools; Naif's signature is smaller and credits him as preparer. Compare visible artwork, excluding transparent file margins. Use navy on light backgrounds and white on dark backgrounds, preserving the original shape. Both marks share the footer background; do not frame the signature in a separate card.
9. Motion should explain a change or relationship. Repeating motion needs play and stop controls and must respect reduced-motion preferences. Follow the timing rules in the digital experience standards.

## Verify and deliver

- Check final dimensions, mobile layout, headings, data, unclipped letters and non-overlapping logos.
- Visually verify Arabic `salt` alternates. A loaded font-family name alone does not prove that alternates are active.
- Check Arabic, English, numbers, currency and dates after export, including font consistency.
- Review contrast, links, actions, loading and error states as appropriate to the output.
- For images, protect important information from platform overlays while extending background and pattern across the full canvas.
- State what was actually verified, missing assets and test limitations. Reading or downloading instructions does not guarantee a correct result.

## Output-specific rules

### Websites and tools

In a Hatta tool footer, make Hatta's logo visually dominant and Naif's signature smaller. Use a shared background, navy signature on light surfaces and white on dark surfaces. Judge visible artwork bounds, not image-file width. Refer to section 04 and `assets/brand-marks.css` in the guide.

Preserve calculations and data. Apply only the requested identity scope. Distinguish Arabic main headings, subheadings, body text and controls. Test keyboard access, focus, mobile, tables, loading and errors. Keep the tool name and primary action accessible without an oversized header. Export results with values, units and context; omit technical hosting addresses unless requested. Apply the digital experience checklist.

### Presentations

Use 16:9 and one idea per scene. Start at 32–44 pt for headings and 20–24 pt for body text, then check the viewing distance. Use explanatory motion within a slide when useful instead of repeating content. Represent participants according to their actual roles. Check navigation, full screen and a static export if required.

### Reports

Lead with the outcome, then evidence, options, recommendation and responsibility. Use A4 where appropriate, margins of at least 18 mm and body text at 11–12 pt. Review Arabic wrapping, tables and page breaks. State units, assumptions and sources. Replace placeholders before delivery. Check fonts after PDF export; generating a file alone is not quality assurance.

### Images and link previews

Choose dimensions for the channel. Start at 1200 × 630 for link previews, 1080 × 1350 for 4:5 posts and 1080 × 1920 for 9:16 content. Check the main message at reduced size. Protect important content from current platform controls while extending the background and pattern across the entire canvas. Do not assume one safe margin works everywhere or permanently leave interface areas empty. Use original fonts and logo assets; generated artwork does not replace typesetting in the approved font.

### Diagrams and financial information

Name parties, arrows and units. Distinguish cash movement, ownership and decision authority. Keep color meanings consistent across scenes. Separate illustrative examples from actual data. Recheck calculations when new data is introduced; do not alter an existing calculation as part of a branding-only task.
